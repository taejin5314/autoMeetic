# Live Coach + Memory Tree — Proactive In-Meeting Context Surfacing — Design Spec

**Date:** 2026-05-28
**Status:** Draft — pending implementation
**Stream type:** Net-new feature (first proactive/agentic surface in autoMeetic)
**Related:**
- Pipeline Orchestration (`2026-05-28-pipeline-orchestration-design.md`) — the `PipelineBus` this stream subscribes to
- Deep Ask Multi-Agent (`2026-05-26-deep-ask-multi-agent-design.md`) — Memory infrastructure reused for cluster retrieval
- Memory Library Chat (`2026-05-23-memory-chat-design.md`) — `SearchService` substrate
- Glossary Variants & Inline Highlights (`2026-05-25-glossary-variants-and-highlights-design.md`) — `normalizePreserveTerms` is extended here

This is the first product step in option 6 of the strategic brainstorm (Live Coach + privacy/CJK positioning). It directly answers competitive pressure from OpenHuman (general-purpose "always-on background thinking") by going **vertical-deep**: a meeting-only proactive surface that exploits autoMeetic's unique strengths (memory + glossary + bot-free capture).

## One-line

Add a `CoachSubscriber` to the `PipelineBus` that watches live transcripts; on (a) **past-meeting references** (keyword-triggered) it retrieves the closest **Memory Tree cluster summary** and (b) on **glossary variant→canonical normalizations** it emits a "term mismatch" notice. Surface both as cards in a new **"Coach" mode of the right shelf**. Memory Tree v1 = one cluster level (cosine-similarity grouping with LLM-generated cluster summaries, rebuilt on meeting end).

## Why this stream

The 2026 AI-meeting-assistant category is shifting from reactive note-taking to **proactive agentic surfaces** (Fireflies Live Assist, OpenHuman background thinking, tl;dv coaching). autoMeetic has the table-stakes (transcript + summary + Memory Ask + Deep Ask) and several genuine differentiators (bot-free capture, multilingual CJK, sophisticated glossary, whiteboard agent) — but no proactive surface during meetings. The closest existing capability, Answer Assist, is **user-pulled** (hotkey).

OpenHuman's playbook is *breadth* (118 integrations, general personal AI, Google Meet bot join, mascot). autoMeetic's wedge is the inverse: **vertical depth with privacy-first bot-free capture**. The Live Coach is the strongest single product move that exploits this wedge:
- **Past-context surfacing** uses autoMeetic's unique memory depth (already built: search + Deep Ask + glossary). OpenHuman's memory is a jumble of email + Notion + code; autoMeetic's is *only meetings*, so its tree is semantically clean.
- **Glossary mismatch surfacing** leverages autoMeetic's STT-mishearing variant detection — a feature no competitor has.
- **Right-sidebar feed** (calm, dismissible, ambient) is in deliberate contrast to OpenHuman's mascot — autoMeetic stays professional/quiet.

**Memory Tree** (hierarchical compressed summary trees, inspired by OpenHuman's design but scoped to meetings) is bundled because it (1) is the natural data substrate Live Coach needs to surface relevant context cheaply, and (2) is itself a Deep-Ask-quality-of-life improvement.

## Success criteria

1. **`coach` shelf mode visible:** RightShelf gains a third tab (`whiteboard` | `actions` | `coach`); App's shelf-toggle button cycles to it. Default mode unchanged; user opts in.
2. **Past-context card:** During a live meeting, when the speaker uses a keyword like "지난번", "저번", "last time", "previously", "before that", a `past-context` card appears in the Coach feed within ~3s, naming a matched cluster (title + ≤200-char snippet) with a clickable `Open` action that opens the Memory Library to the relevant meeting(s) / cluster.
3. **Glossary mismatch card:** When `normalizePreserveTerms` replaces a variant with its canonical form during translation, a `glossary-mismatch` card surfaces (canonical + heard variant + turn id). No LLM cost.
4. **Memory Tree exists and updates:** Each finalized meeting is assigned to a cluster (cosine similarity ≥ 0.6 with an existing cluster's centroid, else creates a new cluster). The affected cluster's summary is regenerated by a single `gpt-4o-mini` call.
5. **Bus subscription is the integration point:** Coach is added as a new `PipelineSubscriber` in `index.ts`; `transcriptPostProcessor` is NOT edited (proves the orchestration stream's value).
6. **Rate limits enforced:** past-context max 1 per minute + same cluster id deduped within 5 min; glossary-mismatch deduped on `(canonical)` within 1 min; total Coach cards ≤5 per minute.
7. **No regression to existing flow:** `npm run typecheck`, `npm run lint`, `npx vitest run`, `npm run build` all clean. Coach disabled (shelf set away) → zero observable difference to existing transcription / translation / whiteboard / memory paths.
8. **Coach UI is calm:** Cards animate in non-intrusively, can be dismissed individually or all, persist in the feed until dismissed or meeting ends. No popups, no toasts, no audio — sidebar feed only.
9. **i18n complete:** New Coach strings present in all 4 locale JSONs (en/ko/ja/zh); locale parity test green.
10. **Privacy stays bot-free:** No external network calls beyond existing LLM/search paths. Coach reuses existing OpenAI infrastructure; no new third-party services.

## In scope

### Memory Tree v1 (one cluster level)

- **Schema bump v5 → v6** — new tables:
  - `meeting_clusters (id PK, title, summary, centroid BLOB, member_count, created_at, updated_at)`
  - `meeting_cluster_members (cluster_id, meeting_id, PRIMARY KEY (cluster_id, meeting_id), FK CASCADE on both)`
  - Index on `meeting_cluster_members.meeting_id` for reverse lookup
- **Repository methods** (`MemoryRepository`): `insertCluster`, `updateClusterSummary`, `addClusterMember`, `getClusterByMeeting`, `listClusters(limit)`, `findNearestClusterToCentroid(centroid, threshold)`, `recalcClusterCentroid(clusterId)`.
- **Builder** `src/main/memory/memoryTreeBuilder.ts`:
  - `rebuildForMeeting(meetingId)`: compute meeting centroid as the average of its `segment_embeddings` vectors; find nearest existing cluster via cosine similarity; if `sim ≥ 0.6`, add to that cluster + recompute centroid + LLM-regenerate cluster summary; else create new cluster with the meeting alone + LLM-generate its summary.
  - LLM call: `gpt-4o-mini`, prompt = "Summarize these N meetings (titles + their short summaries) in ≤500 chars; return a single line title + a 2-3 sentence summary." Single call per affected cluster.
  - Triggered by the existing `PipelineEvent: meeting-ended` (already emitted by the lifecycle bridge).

### Coach event detection (`src/main/coach/coachService.ts`)

- **`past-context` detector**:
  - On `turn-finalized`, regex-screen with `/(지난번|저번|이전에|먼젓번|last time|previously|before that|remember when|earlier we|the other day)/i`. Cheap pre-filter.
  - If matched and rate limit OK (max 1/min, per-meeting state): embed the turn text using existing `EmbeddingService.embedQuery`, call `repo.findNearestClusterToCentroid(embedding, 0.6)`, exclude the current meeting's cluster.
  - If a cluster matches, emit `past-context` event with `{ clusterId, clusterTitle, snippet (cluster.summary.slice(0,200)), turnId }`.
- **`glossary-mismatch` detector**: relies on the extended `normalizePreserveTerms` (Phase 3) reporting which variants were normalized. The coach subscriber receives a new pipeline event `glossary-normalize-applied { id, pairs: [{ canonical, variant }] }` and emits a `glossary-mismatch` Coach event per unique pair (deduped per `(canonical)` within 1 min).
- **Rate limit/dedup** module-local maps: timestamps per event type / per cluster id / per canonical term. Clears on meeting-ended.

### `normalizePreserveTerms` extension (Phase 3)

- Today returns `string`. Extend to ALSO return the list of `(variant, canonical)` replacements made — without changing the returned text. New signature: `normalizePreserveTerms(text, entries) → { text, pairs: { variant; canonical }[] }` (or a sibling function; choose to minimize call-site churn).
- All existing call sites (`transcriptPostProcessor` translation path, Memory Chat synthesizer, Deep Ask synthesizer, Answer Assist, whiteboard) updated to take `.text` (or pass through the result if they later want pairs). v1 only the translation path emits the pairs onto the bus.

### PipelineBus integration

- New event type `glossary-normalize-applied` in `PipelineEvent` union.
- `transcriptPostProcessor` emits it from the translation result path (right after the normalize call) — single line addition.
- `CoachSubscriber` in `src/main/pipeline/subscribers/coachSubscriber.ts` subscribes to `turn-finalized` + `glossary-normalize-applied` + `meeting-ended` (clears coach state).
- `index.ts` registers the subscriber (1 line) and wires the `meeting-ended` bridge to the MemoryTreeBuilder (1 line).

### IPC + preload

- Main → renderer: `coach:event` channel carrying the typed `CoachEvent` payload.
- Preload bridge: `window.electronAPI.coach.onEvent(handler) → unsubscribe`.
- Preload type addition.

### Renderer

- `src/renderer/coach/useCoachFeed.ts` — subscribes to `coach:event`, accumulates a rolling list (cap ≈ 30 cards), supports dismiss(id) + clearAll().
- `src/renderer/coach/CoachFeed.tsx` — presentational; renders cards by type, each with an icon, a body, an action (`Open` for past-context jumps to Memory Library + the cluster's most recent meeting; nothing for glossary-mismatch beyond dismissal).

- `src/renderer/App.tsx` — extend `usePanels` shelf type to include `'coach'` (already extracted hook); shelf-toggle cycles through `whiteboard → actions → coach → closed`. Behavior-preserving for users who don't use coach.

## Out of scope (deferred)

- **Multi-level Memory Tree** (super-clusters). v1 = one level only.
- **Cluster re-clustering** beyond reassignment-on-new-meeting (no periodic re-balance, no merge/split).
- **Coach proactive types beyond past-context + glossary-mismatch**: no clarifying-question suggestions, no drift detection, no speaker balance, no action-item live tracking, no response drafts.
- **Inline transcript markers** for Coach. Sidebar only.
- **Audio / TTS / voice cues / mascot.** Sidebar feed only.
- **Coach card click-through deep linking** beyond opening Memory Library at the cluster's latest meeting.
- **Learning/feedback loop** (dismissing doesn't change future behavior; no thumbs up/down).
- **External integrations** (Notion/Linear/Jira/email) — separate future stream in option 6's roadmap.
- **Local LLM option** — separate future stream (option D).
- **CJK-native deepening** (honorifics, business hierarchy detection) — separate future stream (option E).
- **Whiteboard reactive coach card** (Coach doesn't trigger whiteboard generation).
- **Real-time bilingual coaching** (target-language clarifications for non-native speakers).
- **Coach events fired into the meeting summary at end** — out of scope; Coach is live-only.

## Key design decisions

| Decision | Choice | Reasoning |
|---|---|---|
| Integration point | New `CoachSubscriber` on `PipelineBus` | Proves the orchestration stream's "add consumer without editing transcriptPostProcessor" goal. Zero hot-path edits. |
| Bundle Memory Tree | Yes (user choice; spec flagged the alternative) | Memory Tree is the substrate that makes past-context surfacing cheap + clean. Without it, every event would do a Deep Ask round-trip. |
| Tree depth v1 | One cluster level | Simpler schema, simpler builder; super-clusters are a v2 optimization when meeting count grows past a few dozen clusters. |
| Cluster similarity threshold | Cosine ≥ 0.6 | Empirical conservative default; favors new clusters when uncertain. Env-tunable (`MEMORY_TREE_CLUSTER_THRESHOLD`). |
| Past-context detection | Regex pre-filter + embedding lookup | Regex is cheap, prevents LLM/search spam. Embedding lookup is fast (centroid table). No LLM call per turn. |
| Glossary mismatch | Free, zero-LLM, hooks into existing normalize step | Reuses existing infrastructure; the normalize step ALREADY knows which variants it normalized. We just surface that. |
| Surface style | Right-sidebar feed (calm, ambient) | Contrasts with OpenHuman mascot. Professional/quiet. Dismissible. No popups, no audio. |
| Rate limits | Strict (1/min past-context, 5/min total, 5-min cluster dedup, 1-min canonical dedup) | Anti-annoyance is critical for proactive surfaces. Better silent than spammy. |
| Where Coach state lives | Main process (`coachService`) | Rate-limit/dedup state belongs with the event source. Renderer just displays. |
| Cluster summary regeneration | LLM `gpt-4o-mini`, single call per affected cluster on meeting-end | Cheap; only fires once per cluster per meeting-end; cost negligible vs Deep Ask. |
| Open action | Routes to Memory Library + selects cluster's latest meeting | Reuses existing Memory Library UI; minimum new UX. |
| Coach `meeting-ended` behavior | Clear in-flight rate-limit state; preserve already-emitted cards until user dismisses | Prevents stale carry-over to next meeting; respects user's dismiss choice. |

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Past-context cards noisy (false positives on keyword) | Conservative similarity threshold; per-meeting rate limit; same cluster deduped 5 min; cards dismissible. If noisy in smoke, raise threshold to 0.7. |
| Cluster quality poor for small DB (< ~5 meetings) | Builder creates singleton clusters; past-context only fires when a real match is found above threshold. Less noise > less coverage early. |
| LLM cost creep from cluster summary regeneration | One call per meeting-end max (only the cluster receiving the new member regenerates); `gpt-4o-mini` ~$0.0001-0.001 per call. Negligible. |
| Glossary-mismatch overlap with renderer highlights | Glossary highlights are existing visual ambient signal; Coach card is an active log. Different surfaces, complementary. Dedup ensures one card per (canonical) per minute. |
| Bus subscriber failure breaking live pipeline | PipelineBus already isolates errors (try/catch + .catch); a Coach failure logs but doesn't break the feed/memory/whiteboard. |
| Schema bump on existing user DBs | `CREATE TABLE IF NOT EXISTS` works for new tables; `schema_version` row bumped to 6. Existing memory data untouched. |
| `normalizePreserveTerms` signature change breaks call sites | Spec uses additive sibling function OR returns `{ text, pairs }` and updates call sites mechanically. Behavior of `.text` is identical; only the bus emits the pairs. Existing tests stay green. |
| Live performance impact (every turn does regex + maybe embed) | Regex is microsecond; embedding only when regex matches AND rate limit OK (max 1/min). Off the hot path. |
| Empty Coach feed feels broken to user | Empty state: "Listening — proactive surfaces appear here". |
| Coach card "Open" deep-link complexity | v1: opens Memory Library at the cluster's most recent member meeting. No new routing. |
| Coach mode toggle confusion (3-way shelf) | Cycle order whiteboard → actions → coach → closed (consistent with current 2-way); persists per session. |
| RightShelf prop drilling for coach | RightShelf already takes shelf-mode prop; adding `'coach'` is one union variant + one render branch. Small surface. |

## Verification approach

Per `CLAUDE.md` phase verification convention:

1. **Each phase:** `npm run verify:phase <N>` shows `VERDICT: ✅ Phase N verified`. `npm run build` clean (touches main + renderer + preload).
2. **Final:** `npm run verify` + `npm run build` clean.
3. **Manual smoke (deferred to user):**
   - Start a meeting; say "지난번 OKR 얘기..." or "last time we discussed..." (with an existing relevant cluster); expect past-context card within ~3 seconds.
   - With glossary entries containing variants, say a variant during a meeting; expect a glossary-mismatch card.
   - Coach feed survives toggling shelves; cards dismissable; meeting end clears in-flight rate-limit (so a new meeting starts fresh).
   - Spam keywords → rate limit holds (≤1/min past-context, ≤5/min total).
   - Coach disabled (shelf elsewhere) → existing UX unchanged.
   - 4 locale switches still work; new Coach strings translated.

## Open questions / explicit non-decisions

- **Similarity threshold 0.6?** Plausible default; env-tunable. Manual smoke will dial it in if noisy.
- **Cluster title language** — LLM picks based on member meetings; v1 doesn't force a UI language. v2 may localize cluster titles by UI language.
- **What about meetings without embeddings yet?** Skip cluster assignment for those; the embedding backfill stream already handles missing embeddings. After backfill completes, rebuild can be triggered.
- **Should past-context card include a one-line LLM-generated explanation tying past↔present?** Tempting but v1 = just the cluster summary snippet. v2 could LLM-generate a "this matches because…" line.
- **Coach card persistence across app restart?** No — feed is in-memory for the current session. v2 might persist to localStorage.

## Self-review notes

The bundling decision (Memory Tree + Live Coach in one stream) was the user's call despite my recommended split. To manage the bundled scope, the plan keeps each component genuinely independent:
- Memory Tree (Phase 1) can be tested + shipped alone (it builds clusters even without Coach reading them; Deep Ask could later benefit too).
- Coach (Phases 2-5) consumes Memory Tree but degrades gracefully if no clusters exist (no card surfaced, no error).

This stream is also the **first explicit demonstration that the PipelineBus orchestration stream delivers its promised value** — a new consumer added in one line with zero `transcriptPostProcessor` edits. If this stream succeeds cleanly, it validates that architectural investment.

The competitive framing matters: this is autoMeetic's response to OpenHuman's category-leading "always-on background thinking," but **vertical-focused** and **calmer** (sidebar vs mascot). The "Coach" should never feel like a chatty assistant — it's an ambient companion that produces a card only when it has something genuinely valuable to say.
